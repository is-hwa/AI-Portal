# AI 모델 비교 포털

사내에서 "어떤 AI를 쓸지" 판단할 때 근거가 되는 수치를 자동으로 모아 비교하는 웹 포털입니다.
API로 호출하는 상용 모델과 자체 서버에 올려 쓰는 오픈소스 모델을 분리해서 비교합니다.

---

## 1. 화면 구성

| 탭 | 용도 |
| --- | --- |
| **API 모델** | Claude·GPT·Gemini·Grok 등 API로 호출하는 상용 모델 비교 |
| **로컬 오픈소스** | 자체 서버·PC에 직접 올려 쓸 수 있는 모델 비교 (파라미터·VRAM·라이선스 포함) |
| **용어 정리** | AI 용어 설명 16개 |
| **업데이트 관리** | 자동 수집 결과를 사람이 검토하고 반영하는 화면 |

각 비교 탭은 **능력(벤치마크) / 속도·비용 / 특화 영역** 세 가지 축으로 나뉘고,
최대 4개 모델을 선택해 레이더 차트로 겹쳐 볼 수 있습니다.

---

## 2. 데이터는 어디서 오는가

**모든 수집처가 무료이고 API 키 없이 또는 무료 티어로 동작합니다.**

| 수집처 | 무엇을 주는가 | 비용 |
| --- | --- | --- |
| **Artificial Analysis Data API** | 성능 지수 3종, 속도, 가격, 1건당 실측 비용 | 무료 티어 **하루 100건** |
| **Artificial Analysis 모델 페이지** | 1건당 비용의 입력·추론·답변 내역, 추론 토큰 수 | 무료 (API 한도 안 씀) |
| **HuggingFace Hub API** | 가중치 공개 여부, 파라미터 수, 라이선스, 특화 태그, 신규 트렌딩 | **무제한·키 불필요** |
| **Playwright 헤드리스 브라우저** | AA API가 막혔을 때의 폴백 | 무료 |
| **Google Custom Search** | 뉴스 스니펫 (선택) | 하루 100건 무료 |

### 자동 / 수동 구분

- **매일 새벽 3시 자동 실행** — 추적 중인 제공사의 신규 모델 감지, HuggingFace 신규 트렌딩 감지,
  추적 중인 모델의 지표 갱신. 새벽 3시에 PC가 꺼져 있었으면 **서버를 켜는 즉시 놓친 점검을 따라잡습니다**
  (마지막 점검이 20시간 이상 지났을 때)
- **버튼으로만 실행** — 카탈로그 전체 스캔, 파라미터 보강, 가중치 검증
  (한 번에 수십 건이 나와 검토 큐가 넘치고 AA 무료 한도를 소모하기 때문)
- **확실한 건 자동 반영** — 최신화가 목적이라 아래 두 가지는 확인 없이 바로 비교표에 들어갑니다.
  반영 내역은 업데이트 관리 화면의 **"최근 자동 반영 내역"**에서 보고, 잘못 들어간 모델은 거기서 삭제합니다.
  - 기존 모델의 지표 변경 (AA 숫자 그대로라 판단할 게 없음)
  - 추적 중인 제공사의 새 주력 모델, 야간에 발견한 오픈소스 신규 모델 (탭 분류와 가중치 검증이 확정되는 경우만)
- **판단이 필요한 것만 검토 대기** — 같은 제공사의 하위 변형, 규칙상 오픈소스인데 가중치를 못 찾은 모델,
  버튼으로 돌린 카탈로그 스캔 결과는 사람이 **추가/무시**를 눌러야 들어갑니다
- **같은 모델의 변형은 하나만** — 추론 강도 표기만 다른 변형(`(medium)`/`(high)`)이 이미 있으면 자동 추가하지 않고,
  검토 대기에도 한 개만 남깁니다
- **무시·삭제는 기억됨** — 무시한 후보나 비교표에서 지운 모델은 다음 점검 때 다시 올라오지 않습니다
  (추론 강도 표기만 다른 변형도 함께 걸러짐)
- **새 모델의 탭은 자동 판정** — 제공사+이름 규칙상 오픈소스이고 HuggingFace에 가중치가 실제로
  있어야 로컬 오픈소스 탭, 아니면 API 탭으로 들어갑니다

## 3. 실행 방법

### 개발
```bash
npm install
npm run dev      # 프론트 (5173)
npm run server   # 백엔드 (3001)
```

### 배포 (단일 프로세스)
```bash
npm run build
node server/index.js
```
`http://localhost:3001` 하나로 프론트와 API가 함께 뜹니다.

> **주의:** 프론트는 `/api/models`를 런타임에 호출합니다. 정적 파일만 따로 올리면
> API 호출이 갈 곳이 없어 빌드 시점 스냅샷으로 고정되므로, 반드시 백엔드와 함께 띄워야 합니다.

### 환경 변수
`.env.example`을 복사해 `.env`로 사용합니다. **전부 비워도 동작합니다**
(AA 키가 없으면 헤드리스 브라우저로, Google 키가 없으면 고정 URL 스크랩으로 자동 폴백).

## 4. 설계상 중요한 판단들

실제 데이터를 확인하고 내린 결정들입니다. 추측이 아니라 검증 결과에 근거합니다.

### 4-1. 특화 태그는 AA 지수로 추론하지 않는다

처음엔 "코딩지수가 높으면 코딩 특화"로 분류하려 했으나, **AA의 세 지수는 순위가 거의 일치**했습니다.
59개 모델에서 `코딩 백분위 − 종합지능 백분위`의 스프레드가 **최대 0.03**에 그쳤습니다.
세 지수가 사실상 같은 것을 재고 있어서, 여기서 특화를 뽑아내면 **데이터에 없는 구분을 지어내는 셈**입니다.

→ 대신 **제공사가 HuggingFace에 직접 단 태그**(`finance`, `tool-use`, `long-context`, `code`)와
`pipeline_tag`를 근거로 씁니다. 라이선스와 함께 검색 응답에 이미 포함돼 **추가 호출이 없습니다.**

### 4-2. 오픈소스 판정에 "가중치가 실제로 공개됐는가"를 확인한다

AA 카탈로그는 `Qwen3.8 Max` 같은 **가중치 비공개 상용 티어**도 같은 제공사라는 이유로
오픈소스로 통과시킵니다. 로컬 도입 판단이 목적인 화면에서 **못 돌리는 모델을 추천**하는 셈입니다.

→ HuggingFace에 실제 체크포인트가 있는지 확인하고, 없으면 **"가중치 미확인" 뱃지**를 표시합니다.
전수 검사에서 4건이 걸러졌습니다 (Qwen3.8 Max, MiMo-V2-Pro, Solar Pro 4, Devstral Medium —
모두 실제 API 전용 상용 티어).

### 4-3. 반올림 차이는 변경으로 보지 않는다

AA 공식 API가 막혀 헤드리스 브라우저로 폴백하면 **화면에 반올림돼 표시된 값**을 읽어옵니다.
실제 야간 실행에서 변경 149건 중 **83건이 `53.4 → 53` 같은 허위 변경**이었고,
그대로 적용하면 오히려 데이터 정밀도가 깎입니다.

→ 새 값이 기존 값의 반올림으로 설명되면 변경이 아닌 것으로 처리합니다. 149건 → 66건으로 줄었고,
남은 66건은 전부 실제 변화이거나 빈칸 채움입니다.

### 4-4. 데이터가 없는 컬럼은 자동으로 숨긴다

AA 무료 티어가 주지 않는 지표(컨텍스트 윈도우 등)는 앞으로도 거의 안 채워집니다.
채움률이 **20% 미만인 컬럼은 자동으로 숨기고**, 숨긴 이유를 표 아래에 밝힙니다.
지표가 바뀔 때마다 사람이 컬럼을 빼는 작업이 필요 없습니다.

### 4-5. 가격 0은 "무료"가 아니라 "가격 정보 없음"이다

AA는 호스팅 API 가격이 없는 모델에 0을 넣습니다. 카탈로그 673개 중 **23개가 입력·출력 모두 정확히 0**이고,
대부분 Gemma·Phi-4·Olmo 같은 직접 받아 쓰는 오픈 웨이트 계열입니다.
그대로 두면 화면에 `$0`으로 찍혀 **공짜라고 주장하는 셈**이고, "최저가" 선별에도 엉뚱하게 뽑힙니다.

→ 0은 `null`로 바꿔 "—"(모름)로 표시합니다.

### 4-6. AA 카탈로그는 디스크에 캐시한다

카탈로그 1회 조회에 **7건**(페이지당 1건)을 씁니다. 메모리 캐시만 두면 서버를 몇 번
재시작하는 것만으로 하루 100건 한도가 날아갑니다(개발 중 실제로 429를 맞았습니다).
→ 6시간 디스크 캐시로 재시작에도 유지됩니다.

### 4-7. 신규 모델은 "같은 달 출시"도 잡는다

우리 데이터의 출시일은 `YYYY-MM`까지만 있습니다. 처음엔 "우리 최신 모델보다 출시 월이 늦은가"로
신규 여부를 판단했는데, 그러면 **같은 달에 나온 신모델을 전부 놓칩니다.** 실제로 Claude Fable 5.1과
같은 2026-09에 나온 Claude Opus 5.5, GPT-6 Astra와 같은 달의 GPT-6 Sol이 누락됐습니다.

→ 같은 달까지 포함하고, 대신 "이미 추적 중인가"를 이름·slug로 직접 확인해서 걸러냅니다.

### 4-8. 단가 대신 "1건당 실측 비용"과 "추론 비용"을 함께 본다

AA 무료 티어가 주는 성능 지표는 종합지능·코딩·에이전틱 **3개가 전부**입니다(개별 벤치마크는 유료 티어).
대신 AA가 평가 문제를 **실제로 풀게 하는 데 쓴 비용**을 속도·비용 탭에 넣었습니다.
단가(100만 토큰당 가격)만으로는 추론 모델의 실제 비용을 알 수 없기 때문입니다.

| 모델 | 입력 단가 | 1건당 실측 비용 | 입력 | **추론** | 답변 | 추론 토큰/건 |
| --- | --- | --- | --- | --- | --- | --- |
| Claude Fable 5.1 | $10 | $7.63 | $3.73 | **$2.36** | $1.54 | 47,240 |
| Claude Opus 5.5 | $4 | $5.98 | $3.60 | **$1.68** | $0.70 | 83,929 |
| GPT-6 Astra | $10 | $2.31 | $1.46 | **$0.43** | $0.42 | 8,582 |

- **총액이 아니라 1건당으로 비교합니다.** 처음엔 평가 전체 비용(총액)을 넣었는데, 모델마다 푼 문제 수가
  1,246~2,524개로 달라서 총액은 효율이 아니라 문제 수 차이에 좌우됐습니다
  (총액으론 GPT-5.6 Sol이 Grok 4.6보다 47% 비싸 보이지만 1건당은 $1.99 vs $1.86).
- **추론 비용은 따로 봐야 합니다.** Opus 5.5는 추론 토큰을 GPT-6 Astra의 약 10배 씁니다. 다만 대부분 모델에서
  **가장 큰 비중은 입력(긴 문맥·캐시)**이라, "추론을 많이 해서 비싸다"만으로는 설명되지 않습니다.
- **출처**: 1건당 총액은 AA 무료 API, 입력·추론·답변 내역은 무료 API에 없어 **AA 모델 페이지**에서
  읽습니다(헤드리스 브라우저, API 한도 안 씀). 페이지 한 곳에 160여 개 모델분이 들어 있고,
  로딩이 가끔 빠져서 최대 4번 재시도합니다. 값이 있는 모델: API 12개 중 8개, 오픈소스 60개 중 22개.
- 표의 "1건당 실측 비용" 셀에 마우스를 올리면 입력·추론·답변 내역이, "1건당 추론 비용" 셀에는 추론 토큰 수가 보입니다.

### 4-9. 모델 이름 매칭은 토큰 집합으로 비교한다

AA와 HuggingFace가 같은 모델을 다르게 표기합니다.

| AA 표시명 | HuggingFace 리포 |
| --- | --- |
| `Llama 3.3 Instruct 70B` | `meta-llama/Llama-3.3-70B-Instruct` (어순 다름) |
| `Jamba 1.7 Large` | `ai21labs/AI21-Jamba-Large-1.7` (접두사 + 어순) |
| `Hermes 4 - Llama-3.1 405B` | `NousResearch/Hermes-4-405B` (AA가 더 김) |

접두어 비교로는 오탐이 14건 났습니다. **토큰 집합 양방향 포함**으로 바꾸고,
버전 안의 점을 먼저 제거(`3.1` → `31`)해 `Hermes-3`과 `Hermes-4`가 섞이지 않게 했습니다.
오탐 14건 → 4건(전부 진짜)으로 줄었습니다.

## 6. 현재 상태와 한계

### 데이터 현황 (API 10개 / 오픈소스 59개)

API 탭은 제공사별로 **최고 성능 2개 + 최저가 2개**를 뽑아 `$0.04 ~ $10`(250배) 가격대를 함께 봅니다.

**오픈소스 59개 기준 채움률**

| 항목 | 채움률 |
| --- | --- |
| 성능 지수(종합지능) | 100% |
| 라이선스 | 100% |
| 특화 태그 | 100% |
| 파라미터 / VRAM | 63% |
| 가격·속도 | 63~71% |
| 컨텍스트 윈도우 | 3% (자동 숨김) |

### 알려진 한계

- **AA 무료 티어 하루 100건** — 카탈로그 스캔을 하루에 여러 번 돌리면 한도에 걸립니다
- **파라미터 63%** — AA 무료 티어에 해당 필드가 없어 이름 파싱 + HF 조회로 채웁니다.
  여러 정밀도가 한 리포에 섞인 경우 값이 부풀려질 위험이 있어 **일부러 비워둡니다**
  (틀린 값을 채우는 것보다 모른다고 하는 쪽을 택함)
- **한국어 성능 지표 없음** — AA에 한국어 벤치마크가 없습니다. 현재는 HF 언어 태그 기반
